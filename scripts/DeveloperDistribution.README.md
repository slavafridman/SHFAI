# DEVELOPER / TEST SNAPSHOT — NOT A SHIFTER RELEASE

This distribution contains the existing fixture-slice backend import closure and
one selected compiled Angular browser profile. It is not feature-complete,
production/authentication-ready, a deployment, or a release certificate. New
API baselines and remaining milestones are not implemented by packaging.

**Test-tool history and validation scope:** historical source Vitest **4.0.8**
runs had an intermittent Worker-start timeout before test collection. The
explicitly approved **4.0.9** patch includes upstream PR **9027**, correcting
the vendor's enclosing startup budgets from outer 5 / inner 10 seconds to
published defaults of 90 / 60 seconds. No local timeout override, vendor edit,
automatic retry, pool change or forced-success exit is part of delivery.
The precise underlying OS/Worker-start delay cause remains unproven. Patch
approval alone is not runtime proof: only a specific source build with
`-Validation` that completes both full suites and naturally exits 0 establishes
that run's full-validation result. The supported build without `-Validation`
checks compilation and packaging, not either full unit suite. Vitest is source
test tooling only and is not included in this runtime distribution.

## Contents / prerequisites

- `backend/server.mts` and `backend/populated-server.mts`, their explicitly rooted
  literal relative import closure, `package.json` and lockfile. No test subtree.
- Three sanitized config examples. They are **never automatically loaded**.
- `frontend/browser/index.html` and selected compiled assets; the existing public
  environment has only frozen `appEnv` and relative `apiBasePath: "/api"`.
- `BUILD.md` records actual source HEAD, scoped tracked source changes, selected
  profile, scoped untracked source names, assigned packaging changes, payload
  byte counts/SHA256 and the actual source-checkout validation command. Current
  uncommitted artifact bytes do not establish published source.
- `THIRD-PARTY-NOTICES.txt`, if generated by the selected Angular build.

Use native Windows, Node **24.21.0** / npm **11.19.0**. Backend runtime uses native
`.mts` type stripping, not compiled JavaScript. Runtime dependencies are excluded.
An operator can explicitly run the following **after extraction** in `backend`:

```powershell
npm ci --omit=dev
```

This network/dependency step was not run by the packaging tool. TypeScript,
frontend tooling and tests are intentionally not runtime payload.
Oracle `oracledb` **26.0.0** is locked; the approved Oracle 11g / Thick Client
**19.3** combination requires separately authorized external setup and live
verification. No Oracle client, connection settings or allowance files are
packaged. Delivery does not require or authorize any live connection.

Native write startup now additionally requires the server-only external key
`SHF_NATIVE_COMMAND_COORDINATOR_CONFIG` and an independently approved existing
local coordinator namespace. This intentional requirement applies to old native
write configurations as well as the late feature; read-only operation is
unaffected. Packaging neither reads nor provisions that namespace, allowance
files, employee guards or attempted markers, and never resets a consumed fuse.
No operator packet or example containing actual coordinator paths is shipped.
Configuration and namespace approval/provisioning remain the operator and
architecture owners' responsibility, outside this developer validation.

## Explicit local fixture example (operator-run, not run during delivery)

### Populated isolated TEST packaging (M02)

The separately opted-in `synthetic-full-test` Docker package uses the validated
TEST browser payload and the top-level populated launcher. `READONLY`,
`management`, and `cancellation` are exact, exclusive per-process modes; no
combined grants. This means populated **existing implemented workflows**, not
full legacy parity or completion of remaining milestones. All people/data are
synthetic; the fixture clock is frozen at `2026-11-01T12:00:00.123Z` in UTC, not
real time. Management/C52 transactions affect volatile fixtures only. Oracle
and EMS completion is never asserted. Browser flags are not authorization.

From the source checkout, run exactly one canonical TEST validation, followed
by optional DEV/production builds without repeated full validation:

```powershell
powershell.exe -NoProfile -File scripts/Build-Shifter.ps1 -Profile test -Validation
powershell.exe -NoProfile -File scripts/Build-Shifter.ps1 -Profile dev
powershell.exe -NoProfile -File scripts/Build-Shifter.ps1 -Profile production
powershell.exe -NoProfile -File scripts/Build-LocalDemo-Shifter.ps1 -DemoOptIn synthetic-full-test -Mode READONLY -ReuseValidatedPayload
powershell.exe -NoProfile -File scripts/Test-FullTest-Shifter.ps1 -ContainerChecks
```

See the root README Docker section for operator-only Compose commands.
Packaging probes use network-none ephemeral containers and never replace an
existing demo. Image default production rejects mock startup. Production ZIP
remains fail-closed pending real authentication. The TEST example JSON below
remains inert and is not the populated environment configuration.

The backend defaults to **no usable authentication/configuration**, never
automatic Administrator. To deliberately opt into a loopback-only synthetic
demo, in a fresh PowerShell session inside the extracted `backend`:

```powershell
$env:SHF_APP_ENV = 'dev'
$env:SHF_FIXTURE_CONFIG = Get-Content config-examples/dev.example.json -Raw
$env:SHF_FIXTURE_PORT = '4301'
$env:SHF_FIXTURE_ROWS = '[]'
node server.mts
```

This explicit DEV example opts into a **synthetic Administrator**, not a
password-verified user. Empty synthetic rows do not represent real employee
data. It grants no real authorization and is only suitable for isolated local
development/demo. Do not use an inherited operator/Oracle/native-write session;
do not enable native writes or read a shared database for this example. Close
the terminal afterwards rather than carrying demo configuration into other work.

`test.example.json` is deliberately inert (no approved organization scope and
no Oracle test-scope confirmation); it is not a ready-to-connect configuration.
`production.example.json` disables synthetic login and requests real
authentication, but **startup still fails closed because a real provider is
missing**. Enabling synthetic mode in production is rejected. A production
frontend build does not remove either backend gate.

No secrets are shipped or automatically read. Operators must use separately
approved external environment/secrets mechanisms; never put internal database
settings into browser assets. No `.env` loader, ENV dump, login fallback,
static-server framework or `/api` proxy is added. Serving browser assets with
same-origin `/api` is an external, separately approved concern; this ZIP alone
is not a runnable integrated web deployment.

The builder validates canonical raw ZIP names, exact payload bytes and import
closure, then imports the extracted entrypoint and checks production rejection
with synthetic configuration and forbidden read/native/endpoint factory doubles,
file/DNS/network guards and a driver-import rejection hook. Old native mode
without independent write flags and read-only mode with a stray coordinator key
are rejected. The strict coordinator reader rejects a missing key for a
synthetic target with zero IO. This reader check is not proof that fully enabled
native startup performs no allowance-path validation before that reader:
native binding parsing separately validates an external allowance path.
Fully enabled old native TEST/profileless configurations with a missing or
malformed coordinator key are also rejected before pools or namespace IO.
Only the allowance-path validation uses a literal synthetic filesystem
whitelist, with virtual calls reported separately and no real filesystem
access. No enabled-native success, namespace provisioning or live
infrastructure check is performed.
Extracted browser
assets must pass the selected profile check. Temporary extraction is removed;
the ZIP, stage and isolated frontend build remain under the selected delivery
profile. Normal frontend `dist` and UI-checker output are not delivery outputs.
Private operator packets, runtime dependencies, Oracle Client and same-origin
hosting remain external prerequisites. Artifacts remain **PROVISIONAL** pending
independent QA and final source/closure matching; packaging is not QA sign-off.
