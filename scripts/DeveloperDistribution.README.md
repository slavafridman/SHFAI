# DEVELOPER / TEST SNAPSHOT — NOT A SHIFTER RELEASE

This distribution contains the existing fixture-slice backend import closure and
one selected compiled Angular browser profile. It is not feature-complete,
production/authentication-ready, a deployment, or a release certificate. New
API baselines and remaining milestones are not implemented by packaging.

**Test-tool history and validation scope:** historical source Vitest **4.0.8**
runs had an intermittent Worker-start timeout before test collection. The
explicitly approved **4.0.9** patch includes upstream PR **9027**, correcting
the vendor's enclosing startup budgets from outer 5 / inner 10 seconds to
published defaults of 90 / 60 seconds. No local timeout override, vendor edit,
automatic retry, pool change or forced-success exit is part of delivery.
The precise underlying OS/Worker-start delay cause remains unproven. Patch
approval alone is not runtime proof: only a specific source build with
`-Validation` that completes both full suites and naturally exits 0 establishes
that run's full-validation result. The supported build without `-Validation`
checks compilation and packaging, not either full unit suite. Vitest is source
test tooling only and is not included in this runtime distribution.

## Contents / prerequisites

- `backend/server.mts`, its relative import closure, `package.json` and lockfile.
- Three sanitized config examples. They are **never automatically loaded**.
- `frontend/browser/index.html` and selected compiled assets; the existing public
  environment has only frozen `appEnv` and relative `apiBasePath: "/api"`.
- `BUILD.md` describes the source-checkout build and offline validation commands.
- `THIRD-PARTY-NOTICES.txt`, if generated by the selected Angular build.

Use native Windows, Node **24.21.0** / npm **11.19.0**. Backend runtime uses native
`.mts` type stripping, not compiled JavaScript. Runtime dependencies are excluded.
An operator can explicitly run the following **after extraction** in `backend`:

```powershell
npm ci --omit=dev
```

This network/dependency step was not run by the packaging tool. TypeScript,
frontend tooling and tests are intentionally not runtime payload.
Oracle `oracledb` **26.0.0** is locked; the approved Oracle 11g / Thick Client
**19.3** combination requires separately authorized external setup and live
verification. No Oracle client, connection settings or allowance files are
packaged. Delivery does not require or authorize any live connection.

## Explicit local fixture example (operator-run, not run during delivery)

The backend defaults to **no usable authentication/configuration**, never
automatic Administrator. To deliberately opt into a loopback-only synthetic
demo, in a fresh PowerShell session inside the extracted `backend`:

```powershell
$env:SHF_APP_ENV = 'dev'
$env:SHF_FIXTURE_CONFIG = Get-Content config-examples/dev.example.json -Raw
$env:SHF_FIXTURE_PORT = '4301'
$env:SHF_FIXTURE_ROWS = '[]'
node server.mts
```

This explicit DEV example opts into a **synthetic Administrator**, not a
password-verified user. Empty synthetic rows do not represent real employee
data. It grants no real authorization and is only suitable for isolated local
development/demo. Do not use an inherited operator/Oracle/native-write session;
do not enable native writes or read a shared database for this example. Close
the terminal afterwards rather than carrying demo configuration into other work.

`test.example.json` is deliberately inert (no approved organization scope and
no Oracle test-scope confirmation); it is not a ready-to-connect configuration.
`production.example.json` disables synthetic login and requests real
authentication, but **startup still fails closed because a real provider is
missing**. Enabling synthetic mode in production is rejected. A production
frontend build does not remove either backend gate.

No secrets are shipped or automatically read. Operators must use separately
approved external environment/secrets mechanisms; never put internal database
settings into browser assets. No `.env` loader, ENV dump, login fallback,
static-server framework or `/api` proxy is added. Serving browser assets with
same-origin `/api` is an external, separately approved concern; this ZIP alone
is not a runnable integrated web deployment.
